# Devlog — Milestone 1: the shell becomes a workspace

**Dates:** 2026-06-09 → 2026-06-10
**Status at end:** Milestone 1 complete — M1.1–M1.6 plus a refinement pass —
commits `ea0b46d` (the plan) through `4a65cdf`. Everything short of the editor
is built.

Milestone 0 proved the substrate; Milestone 1 made it the place you work. The
session began as a design conversation (captured in
[MILESTONE_1.md](../MILESTONE_1.md)) and ended with the full workspace model
shipped: projects as native tabbed windows, sessions as bottom-bar tabs, the
Landing/promote flow, two fixed layouts, the worktree fan + `atelier` CLI,
persistence with Claude conversation resume, per-tab agent state, and the
command palette.

## What shipped

- **M1.1** — the fixed Triptych (editor placeholder TL, shell BL, agent R) and
  Split (agent over shell), `⌘\` toggle, per-`(session, mode)` dividers; panes
  are long-lived views re-parented across mode switches so PTYs survive.
- **M1.2** — sessions as tabs: each session owns a pane trio and one hosted
  Claude; the bottom bar; `⌃⌘+hjkl` focus; live tab titles from Claude's own
  transcript; the Landing (see below); tmux-status colors.
- **M1.3** — projects as **native tabbed windows** (`tabbingMode = .preferred`):
  the OS draws the always-visible project strip; `⌘1..9`; `⌘T` = new project
  tab.
- **M1.4** — the worktree fan off the pill (type-to-filter that doubles as
  create; guarded, informative delete) and the `atelier` / `-b` / `-rm` CLI
  riding the M0 socket; worktrees at `~/.local/share/worktrees/`, exactly the
  `ide` script's semantics.
- **M1.5** — persistence: the window→session tree snapshots on quit and
  restores on launch with root validation (orphans surfaced, never silent);
  restored agents `claude --resume` their conversation.
- **M1.6** — the command palette: centered overlay, fuzzy subsequence match,
  chords displayed, recents float, dynamic switch-to rows.
- **Refinement pass** — static project pill; `+`/`⌘⇧T` always from main;
  closing everything reverts to the Launch view instead of quitting; the
  exact-state attention model; grouping/wrap/rename in the strip; notification
  click-to-focus; uncapped tab titles.

## The interesting parts

### The Landing emerged from use, not from the plan

The plan had `⌘T` spawning a bare session in a default cwd — which meant a
Claude process running in `~/repositories`, a junk root nobody asked for. Real
use surfaced the actual need: *"a recents list and a default folder, with a
terminal under it — and sometimes I just want a terminal."* That collapsed into
one mechanism: **a session starts as a Landing** (recents over a plain
terminal, no editor, no Claude) **and is promoted in place** — pick a repo, or
`cd` anywhere and `⌘↩`. Claude only ever spawns on promote, rooted in a real
project, which also deleted most of the first-launch TCC prompt surface. A
Landing that's never promoted is simply the "just a terminal" tab. One state
machine, three wishes.

### The Landing also corrected the tier model

First build put `⌘T`-Landings in the *session* strip — and promoting one to a
different repo would have produced a mixed-repo window, violating
window-= -project. The fix reframed it: **the Landing is a project opener**, so
it belongs at the project tier. `⌘T` became "new project tab" (matching
Ghostty's muscle memory exactly), and the session strip stays homogeneous by
construction. Getting this wrong briefly was cheaper than designing it on
paper: the wrongness was *visible* within a minute of use.

### APFS case-insensitivity ate the app binary

The CLI target was named `atelier`; the app module is `Atelier`. On APFS those
are **the same build product path** — and the same path inside the bundle
(`Contents/MacOS/atelier` vs `Atelier`). The build silently replaced the 4.7 MB
app with the 171 KB CLI; `open` then "launched" a CLI that printed usage text
and exited, while every downstream symptom (no window, no socket) pointed
anywhere but the cause. Diagnosis came from `ls -la` on the bundle: the size
was wrong. Fix: the target and bundled binary are `atelier-cli`; the
user-facing `atelier` name comes from the PATH symlink (`make install-cli`).
Lesson for any SwiftPM project shipping a same-named CLI next to its app:
**case-insensitive filesystems make `Foo` and `foo` one artifact.**

### Native tabs vs `.fullSizeContentView`

With full-size content, the panes were pinned to the contentView top — which
extends *under* the titlebar — so Claude's TUI drew straight through the
project tab strip (and explained the "text wraps oddly at the top edge"
report from M0 days). The fix is one anchor: pin the session area to
`window.contentLayoutGuide.topAnchor`, the region AppKit keeps below
titlebar + tab bar. Blur still reaches the top; content doesn't.

### Pinned session ids made everything else possible

`claude --session-id <uuid>` (one generated per session) turned out to be the
load-bearing trick of the milestone. It gives each session a *known* transcript
file, which yields: per-tab titles that can't collide across same-cwd sessions
(reading the `ai-title` the same way M0's truthful copy reads message text);
`claude --resume <id>` on restore, so a reopened workspace continues its
conversations; and — combined with hooks passing their stdin payload's
`session_id` through `atelier-notify` — agent events that land on the *exact*
tab that fired them, including banner click-to-focus.

### The attention model earned its complexity in three steps

First design: badges only on inactive tabs, cleared on focus. Use revealed two
flaws. (1) A global "activity dot" can't say *which* session wants you — that
died in the design pass. (2) Clearing a seen completion to *nothing* threw away
a true fact: the agent is now **waiting on you**. The shipped model is
exact-state, always visible: **blue dot** working, **peach dot** waiting (peach,
not red — "waiting" isn't an alarm), **peach `!`** explicitly blocked
(permission/question), **green dot** unseen completion, which on focus becomes
*waiting* rather than disappearing. Claude's idle "waiting for your input" ping
arrives on the same Notification hook as real blockers; it's classified by
message body — the one fragile seam (a Claude Code copy change would over-alert,
not under-alert).

### What verification looked like without eyes

A recurring constraint: the agent driving this build could not see the screen
(the window often sat on another Space; per-window capture needs Screen
Recording permission). Two consequences worth recording. A misread AppleScript
result — `13` and `37` concatenated into "1337" — spawned a phantom "window is
off-screen" bug and a reverted fix; the lesson is to distrust stringly-typed
geometry. And the working loop became: verify everything reachable from the
shell (processes, sockets, transcripts, git state, snapshots on disk), then
hand the visual checklist to the human. Notable wins for that loop: the CLI was
proven end-to-end headlessly (window title via AppleScript, worktree on disk
via `git worktree list`), and the persistence round-trip was proven from the
snapshot JSON alone.

## Other decisions worth remembering

- **Hooks merged additively.** The Atelier hook fragment now sits *alongside*
  the dotfiles afplay hooks in `~/.claude/settings.json` (backup kept). Hooks
  are global, so Atelier banners for non-Atelier Claude sessions too — the
  native version of the afplay ping; badges only apply to its own sessions.
- **Quit is the snapshot point.** `applicationShouldTerminate` persists (by
  `willTerminate` the controllers are gone). Closing every window by hand is a
  deliberate "fresh start" and snapshots nothing.
- **The bar is honest chrome.** Static project pill (the branch-pill design
  reflowed the bar on every tab switch); clock with blinking colon; layout
  toggle in the corner; no ctx% (Claude shows its own); no activity dot.
- **Palette is a backstop, not an omni-bar.** Dedicated fast paths (`⌘P`,
  `⌘⇧F`, the fan) stay separate; `⌘⇧P` is where forgotten chords resolve, and
  it displays the chords to teach them.
