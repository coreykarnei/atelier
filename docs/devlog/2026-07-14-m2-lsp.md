# 2026-07-14 — M2.5: the LSP client (definition + diagnostics, nothing else)

TECHNICAL_PLAN §3.3's scope for v1: go-to-definition and diagnostics over
JSON-RPC/stdio to sourcekit-lsp. Both landed; nothing else was built —
no hover, no completion, no rename.

## Shape

- **`LSP.swift`** — `LSPClient`, one per repo root (`LSPRegistry`, spawned
  lazily via `xcrun sourcekit-lsp`, cwd = root, torn down at quit). The
  client is deliberately dynamic (JSONSerialization, not a Codable mirror
  of the protocol): four notifications, two requests. All state on a
  serial queue; completions on main. Server→client *requests* get an
  honestly-empty reply (`workspace/configuration` gets one null per item)
  so the server never stalls waiting on us.
- **Document lifecycle** in `EditorPane`: Swift buffers (and only Swift —
  other languages get no client and stay plain) send didOpen on open,
  full-document didChange debounced 300ms behind the existing dirty
  tracking, didSave on ⌘S, didClose when another file replaces the buffer.
  `lspRoot` is set by both open paths (controller `openInEditor`, session
  restore).
- **Diagnostics are pulled, not awaited**: sourcekit-lsp barely pushes
  (`publishDiagnostics` stayed silent through every live test; its
  `diagnosticProvider` capability is even absent) — the working mechanism
  is LSP 3.17 `textDocument/diagnostic` after didOpen and each debounced
  change. Push is still handled if a server sends it; both flow through
  one path. Rendering: `EmphasisManager` underlines — error red, warning
  peach, info/hint muted; LSP's 0-based UTF-16 positions map through the
  buffer's line starts, and stale ranges that outrun the live text are
  dropped, not clamped. No gutter icons, no popovers; the message text
  waits for a later milestone.
- **Go to Definition**: F12 (the VSCode instinct; function keys carry no
  modifier), menu item under View, palette entry, all gated on an open
  buffer. Same-file results reveal in place; cross-file results ride the
  ⌘P open path, dirty-guard included. No result is a quiet no-op — the
  server may still be indexing, and a missing definition isn't worth a
  dialog. (⌘-click would need CodeEditSourceEditor's internal
  `jumpToDefinitionModel` delegate, which 0.15.2 doesn't expose to AppKit
  hosts — noted for a future vendored patch or upstream bump.)

## Verification — the lspProbe debug

Keystroke injection was flaky this session, so the M0 debug socket grew a
second dev-only command: `{"debug":"lspProbe","path":…,"line":N,"column":M}`
runs definition at that caret in the active buffer and dumps the result
plus the last published diagnostics. Live results against this repo:

- `Theme.terminalBackground` at TerminalPane.swift:138:51 →
  **Theme.swift:186:16**, the declaration (cross-file, package-indexed).
- A deliberately broken in-package file surfaced
  `2:28 [error] Cannot convert value of type 'String' to specified type
  'Int'` in the editor, red underline exactly under the offending string
  (snapshot-verified).
- Standalone files outside the build graph get syntax-only analysis from
  sourcekit-lsp (no sema, so no type errors) — inherent to the server,
  acceptable for v1.

Also learned and worked around: crafted `session.json` test states must be
written *after* the dying instance finishes its own quit-time persistence
(poll for process exit), and `PersistedSession.claudeSessionId` is
required by the decoder — a missing field silently costs the whole
restore.
