# Devlog — Milestone 0: the native two-pane spike

**Date:** 2026-06-01
**Status at end:** Milestone 0 complete; committed to `main` as `ed2f03e`.

The goal of Milestone 0, per [TECHNICAL_PLAN](../../TECHNICAL_PLAN.md) §4, was to
**prove the bet before building the long pole.** Atelier's whole reason to exist is
the claim that owning the terminal emulator natively — instead of delegating to tmux
— buys you truthful copy and real notifications. The editor is the bigger body of
work, but it's *low uncertainty*; the risky, project-defining bet is the
terminal-ownership thesis. So that went first.

By the end of the session the bet was proven, and — more valuably — the spike
surfaced one load-bearing surprise that would have been expensive to discover later.

---

## What shipped

A native macOS SwiftPM app (AppKit + [SwiftTerm](https://github.com/migueldeicaza/SwiftTerm)):

- **Single window, two PTY-backed terminal panes** — `zsh` on the left, the real
  `claude` binary on the right, hosted unchanged. Catppuccin Mocha, native blur.
- **Truthful copy** (the feature that justifies the project) — working in both panes,
  by two different mechanisms (see below).
- **Notification bridge** — a unix-socket listener in the app + an `atelier-notify`
  CLI driven by Claude Code's `Stop`/`Notification` hooks, sharing an `AtelierIPC`
  contract.
- **Stable code-signing identity** — a self-signed cert so macOS persists TCC
  permission grants across rebuilds (`Scripts/make-signing-cert.sh`).
- **Build tooling** — `Makefile`, `bundle.sh`, `Info.plist`, an Edit menu.

Three SwiftPM targets: `Atelier` (the app), `atelier-notify` (the hook CLI),
`AtelierIPC` (shared socket/message contract).

## The interesting part: how truthful copy actually got built

The naive plan was wrong in an instructive way.

### The thesis, and the first proof

The vision's marquee bug: selecting an agent paragraph in tmux returns soft-wrapped
fragments — line breaks jammed mid-sentence — because the multiplexer stores a
character *grid* and discards wrap-intent. The plan's insight: own the emulator and
you keep the distinction between a hard newline and a soft wrap, so copy can
reconstruct logical paragraphs.

Reading SwiftTerm's source confirmed the foundation: its selection logic inserts a
newline only at a *real* linefeed and joins soft-wrapped lines with none. We proved
it with the shell pane — `python3 -c "print('lighthouse ' * 40)"` emits one 440-char
logical line that the terminal soft-wraps across six rows; selecting it and running
`pbpaste | cat -e` showed **zero** `$` markers. One logical line, reconstructed.

### The false positive, and the real test

An earlier "win" — pasting a two-line agent paragraph that came back clean — turned
out to be an artifact: it had been pasted into a **chat input box**, which collapses
newlines into spaces. It *looked* clean and proved nothing. The honest test is
pasting into something that preserves whitespace (Google Docs, `cat -e`, `od -c`).

When we did that with a long agent paragraph, the truth came out: **newlines at every
wrap point, plus leading whitespace on every line.** Truthful copy was *not* working
for the agent pane.

### The load-bearing discovery

The leading whitespace was the tell. Those spaces are *real characters in the grid* —
SwiftTerm joining soft-wrapped lines would never *introduce* per-line indentation. So
those weren't soft wraps. They were separate hard lines, each drawn with literal
gutter spaces.

The cause: **Claude Code's Ink TUI hard-wraps and indents its own output before the
bytes ever reach the PTY.** Ink measures the terminal width, lays the text out itself,
and writes each row padded with spaces. By the time the terminal sees it, the logical
paragraph is *already* shredded into fixed-width, guttered rows. Any emulator — ours,
tmux, VSCode — faithfully stores exactly that grid, because that's what was drawn.

This partially contradicts the vision's stated root cause. For the *shell*, the bug
is tmux's grid. For the *agent pane*, even a perfect native emulator receives a
pre-fragmented grid. **Owning the emulator is necessary but not sufficient.** Finding
that on day one, under a 300-line spike, beats finding it after the editor.

### The conflict, and the decision

This put two of the project's own commitments in direct conflict:

- VISION promises truthful copy of agent paragraphs.
- TECHNICAL_PLAN §2.2 was **[LOCKED]**: "do not parse its output."

For the agent pane you cannot have both. The logical text survives in exactly one
place: Claude's own persisted transcript (`~/.claude/projects/<cwd>/<session>.jsonl`).
Reading it is "parsing its output."

Decision: **narrow §2.2** to "don't parse its *live UI / terminal stream*; reading its
*persisted transcript* for host features like copy is allowed." Spirit intact (we
never scrape or reimplement the agent's interface); promise shippable.

### The mechanism

The trick that makes highlight→markdown work: **markdown markup almost never changes
the letters.** `**bold**`→`bold`, `` `code` ``→`code`, `# H`→`H`. So:

1. On Cmd-C in the agent pane, reduce the rendered selection to a bare
   letters/digits stream (drop gutter, wraps, whitespace, all punctuation).
2. Reduce each assistant message's raw markdown the same way (dropping link URLs and
   code-fence language tags, which carry letters that aren't on screen).
3. Find the selection's stream inside a message, map the match back to source
   offsets, and return that exact markdown slice.
4. No confident match → fall back to a de-guttered literal copy. Never worse than
   before.

Validated offline against the real transcript before any GUI wiring: a screen-style
selection (`environment is set up — home directory /Users/core/repositories with` +
a wrapped, guttered second line) came back as one clean line with the backticks
**restored**:
`environment is set up — home directory `/Users/core/repositories` with all your projects mapped out`.

Then confirmed live: highlighting a full agent paragraph and pasting it elsewhere
yields one clean logical paragraph of perfect markdown. ([`TranscriptCopy.swift`](../../Sources/Atelier/TranscriptCopy.swift),
[`AgentTerminalView.swift`](../../Sources/Atelier/AgentTerminalView.swift).)

## Other decisions worth remembering

- **Substrate: Swift 6 toolchain, Swift 5 language mode.** SwiftTerm's `Color` isn't
  `Sendable`; strict concurrency is more friction than value for a single-window,
  main-thread AppKit app right now.
- **A real Edit menu is load-bearing.** A SwiftPM app has no menu by default, so
  Cmd-C was never wired to the responder chain. Truthful copy literally could not
  fire until the menu existed. Easy to miss; central to the feature.
- **Permission-prompt storm → signing.** macOS won't persist TCC grants for
  ad-hoc/unsigned apps (the designated requirement is the binary hash, which changes
  every build). A stable self-signed identity fixed it. Also: launching the panes in
  `~/repositories` instead of `$HOME` avoids Claude enumerating `~/Desktop` /
  `~/Documents` / `~/Downloads` on startup, which was most of the prompt volume.
- **OpenSSL 3 `-legacy` quirk.** Homebrew's OpenSSL 3 writes a PKCS#12 MAC that
  Apple's `security` can't verify; `-legacy` produces the importable format.
