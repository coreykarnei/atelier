# Atelier v1.2.0 — 2026-09-21

Starting a session stopped asking questions it had already been told the
answer to, and worktrees got a door of their own. One terminal bug went
with it: the scrollback no longer runs away while the agent is typing.

## What changed

**The `+` never asks.** Every `+` — the bare one, each folder's, and
`⌥⌘T` — starts a session immediately, in the worktree you pointed at or
the one the active session lives in, whether or not worktrees are
enabled. The chooser used to stand in front of all of them, asking
"which worktree?" at the moment the gesture had already said, and
defaulting to a row labelled "main checkout" that you had to decode.

**`⎇+` is the door to elsewhere.** Beside the `+`, a new control: the
conifer that labels a worktree folder, with a plus laid over its right
edge and knocked out of it. Click it — or `⇧⌥⌘T`, File → New Session in
Worktree…, or the palette — to start a session somewhere other than
here. It is drawn only where worktrees are both enabled in Settings and
possible (a repo project), and it appears and disappears as you toggle
that setting.

**The chooser is one card.** It opens naming a new worktree, with every
existing one listed underneath and the repo's own checkout last. Type a
branch and `↩` creates it and starts; `↩` on an empty field starts the
highlighted worktree; clicking a row starts that one outright. Typing
puts the row highlight out, so nothing looks armed while the field owns
`↩`; hover and the arrow keys drive that one highlight. The primary
checkout's row now wears the *place* — `main checkout`, with whatever
branch it currently sits on trailing in dim mono — because a linked
worktree is its branch, while the repo's own checkout is a place whose
branch drifts. The card also sat 40pt below centre; it is centred now.

**Sessions in a folder are told apart.** A hairline between adjacent
sessions of one group, and between the last session and its `+`, in the
same ink the `+` uses — plus one between the `+` and the `⎇+` when
there is no folder chrome to separate them. They are placed without a
fade, so they are already right when the selection colour starts to
move.

**A hover pad you can see.** The pad under any bar glyph — the two
strip controls, a folder's `+`, a tab's `×`, the gear — went from 10%
to 16% white, and to 26% while pressed.

**One volume for every `+`.** The per-folder `+` no longer rests at a
whisper and rises in the active folder — every one of them reads at full
strength, with the hover pad doing the feedback. The bare-tabs `+` also
sits where a folder's does, hugging its last tab instead of parking a
row's width out from it.

**The scrollback holds under streaming output.** Scrolling up in a pane
while the agent was mid-turn juddered and then snapped to the bottom.
SwiftTerm decides whether to follow new output by reading a flag that
nothing ever writes — the Mac and iOS views each declare one of their
own, and only the scroller thumb touched it, so the wheel never reached
the emulator and every line of output dragged the viewport down. It now
holds whenever the viewport sits above the live bottom, and resumes
following the moment you scroll back down. The caret, which used to stay
pinned to a row it had scrolled off, now leaves the viewport on either
edge. (Vendored patch 8; meant for upstream.)

## Notes

`docs/devlog/2026-09-21-worktree-door.md` is the entry for the pass —
including the two placement faults that were found by measuring rather
than looking, and the glyph composition that was built and rejected.

New dev probes over the socket: `probe:worktreeAdd` raises the worktree
card, `probe:overlay` dumps a raised card's frame in window points, and
`probe:key` now accepts `down`, `up`, `tab` and `space`.
