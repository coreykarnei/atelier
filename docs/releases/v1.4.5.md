# Atelier v1.4.5 — 2026-09-30

⌘-clicking a path opens the file.

## What changed

**Paths open instead of raising an error.** ⌘-clicking a file or image
path in either pane — a screenshot Claude just read, a file in a stack
trace — showed "The application can't be opened. -50". The path now
opens in its default app, the way a web link always did.

Absolute paths, `~/…`, and paths relative to where the pane is work;
in the shell, relative paths follow your `cd`. A `:line:col` suffix or a
full stop after the path is ignored, and a path that wraps onto the next
row opens whole from either row. A path that doesn't exist does nothing.
Paths printed in a remote session name files on the host, so they don't
open locally; web links there still do.
